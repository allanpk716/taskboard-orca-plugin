# 任务：工单板面板原型修订（A2 —— 三类筛选 + 按人归类）

上一轮 `mock/variant-a.html`（待办优先）方向已获用户认可，但信息架构要按用户批注修改。本轮只产出一个页面：`mock/variant-a2.html`。

先读：`mock/BRIEF.md`（视觉与工程约束，全部继续适用）、`mock/variant-a.html`（沿用其视觉基调与两行式条目）、本文件。

## 用户批注（原话）

> 大方向用这个。我认为应该分三类：等我处理、访客新回复、协作中。有这三类的筛选，并且可以按不同的人进行归类显示

## 新信息架构

### 顶部

- 标题行不变：工单板 · 平台地址（truncate）· ··· 菜单
- 状态行：绿点「连接正常」 + 「N 条通知未读」（有未读才显示，点击滚动到底部通知折叠区）

### 三类筛选（核心改动，替代原底部统计条）

状态行下方一行三个等宽筛选块，兼作统计（数字大、标签小），点选切换下方列表，选中块用强调色（边框或顶边条+亮数字）：

1. **等我处理 N** —— N = 收件箱总数
2. **访客新回复 M** —— M = 访客触动的未处理动态数
3. **协作中 K** —— K = 协作中未读数（无未读时显示总数但弱化）

默认选中「等我处理」。窄屏 390px 下三块等分一行，数字 20px 级、标签 11~12px。

### 「等我处理」列表（默认）

按**往来对象**分组（这是平台术语：每张工单对「我」的另一方），组从上到下：

- 组头：人名/身份 + 该组计数 + 右侧灰字「另等他 M」（该往来对象名下轮到对方的工单数，M>0 才显示，纯属参考）
- 组头人名覆盖四种：普通成员（如「李工」）、访客（如「访客 · 检验科-张三」）、自派自（「我自己」）、待初筛（「待初筛」）
- 组内条目沿用 A 的两行式：第一行工单号（弱化小字）+ 标题；第二行原因徽章 + 等了多久 + 「打开 ↗」；组内按等了多久从长到短排

### 「访客新回复」列表

数据源是访客动态（回复/补全说明/修订说明），按**访客**分组：

- 组头：访客名（如「检验科-张三」）+ 计数
- 条目两行：第一行工单标题（未读加粗亮色，已读弱化）；第二行动作文案（回复了 / 补全了说明 / 修订了说明）· 相对时间 + 「去处理 ↗」
- 未读条目左侧 2~3px 强调色竖条

### 「协作中」列表

按**等待方**分组（工单当前轮到谁），组头如「轮到 李工（指派人）」「轮到 访客」「轮到 本部门」+ 计数：

- 条目两行：第一行工单标题；第二行工单号 + 未读圆点（有未读时）+「打开 ↗」
- 未读条目排前、加亮；已读弱化

### 底部通知折叠区（弱化保留）

「最近通知 · N 条未读」一行折叠摘要，点击展开两行式通知列表（标题 + 原因·时间，未读竖条），此区视觉分量要比三筛选区低一档。

## 假数据（编充足、贴近真实）
